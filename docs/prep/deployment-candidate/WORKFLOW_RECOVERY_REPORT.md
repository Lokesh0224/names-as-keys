# Stage 3E private estimation and reload recovery

The browser now calls the same-origin loopback server for T04. Launch it with `node contracts/scripts/deployment_workflow/serve.mjs` after building the review page. The browser requires an HTTP origin at `127.0.0.1` and disables redirects, caching and credentials for this request. The endpoint validates the host, origin, method, reviewed registrar call, sender, nonce, static arguments and fee ceilings. It verifies the pinned header on an owned Anvil process and uses a read-only upstream proxy. The proxy rejects estimate, write and signing methods, and filters the exact preimage from forwarded reads and responses. The endpoint returns a gas quantity or a generic error. Browser display, journal and application logs omit the unrevealed preimage and raw reveal calldata.

The journal stores the canonical review block, estimate, packet/review digests and public receipt evidence. After a reload, the adapter rebuilds public drafts using the recorded block and checked state, verifies both digests, then prepares a fresh unsigned review. For mined transactions it reconstructs the packet and independently verifies the receipt and mined envelope, exact events, historical state, latest confirmations, separate finalized coverage and current canonical state. T03/T04 recovery can use already mined registration input in memory after checking the successful canonical receipt. Later steps revalidate prerequisite receipts and derive public bindings from the verified reads. Recovery blocks when historical state is unavailable or the anchor, digest or onchain evidence differs. Journal records from the prior implementation lack review anchors and cannot be recovered. Journal hashes detect mismatches in reconstructed data. They provide no authentication against an attacker who can rewrite browser storage and its hashes together.

A public commitment identifier is stored under an owner/root key so changing candidate plans cannot ordinarily bypass the loss policy. Losing the preimage blocks an unrevealed T04 and a replacement commitment in the same plan. A new candidate must verify the previous commit receipt, sender, calldata and canonical finalized coverage, and confirm that the onchain commitment timestamp plus maximum age has elapsed. A missing or ambiguous previous commit record stays blocked. The workflow does not recreate the preimage or automatically retry.

The dedicated server needs Anvil, a trusted local host and public upstream access to historical state. Anvil gas results depend on its execution model and the identified fork state. For the guarded integration run, the same browser transport and HTTP handler targeted the harness's owned Anvil, which contains the locally mined commitment. The fresh-process estimator intended for the browser had no live T04 commitment to estimate in this run.
